Everything about one model on one screen. Today, fixing a failed assertion means hopping between Editor, Query, Quality, DAG and Runs.
  1. Lineage strip. Upstream and downstream models sit above the code. Dashed nodes are the ones your edit will rebuild. Click one to open it in a new tab.
  2. Failures show up where you fix them. A failed @assert shows its row count inline, points at the likely join, and offers the fix. Model references are clickable.
  3. The inspector replaces tab-hopping. Preview, Checks, Columns and Runs for this model sit next to the code. Columns flags missing @col docs.
  4. Preview puts failing rows first. ⌘↵ runs the unsaved SQL against dev, with violating rows highlighted at the top.
  5. Clear blast radius. The action bar spells out what a build will touch, using the existing hash-based change detection, before you press anything.
